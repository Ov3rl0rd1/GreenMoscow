# Веб-интерфейс GreenPlan (ASP.NET Core .NET 10)

Тонкий клиент к движку `greenplan`: загрузка чертежа, статус расчёта, итоги, превью и файлы
результата. Вся расчётная логика — в движке; веб только вызывает его HTTP API.

## Состав

| Путь | Что это |
|---|---|
| `src/GreenPlan.Web/Pages/Index` | загрузка (перетаскивание одного или нескольких .dxf/.dwg — генплан, подоснова — или .zip), категория территории, главный чертёж, модель и превышение норматива с пояснением, панель параметров расчёта и лента последних расчётов |
| `src/GreenPlan.Web/Forms/RunSettingsForm` | параметры расчёта из формы: минимум деревьев, композиция, массивы и изгороди, агенты и их резерв, корнезащита, охранные зоны, напряжение ЛЭП без подписи, граница диапазонов норм, палитра пород |
| `src/GreenPlan.Web/Pages/Jobs/Details` | статус с автообновлением и временем этапов, ключевые цифры, итог и польза, журнал агентов, предупреждения, превью, файлы |
| `src/GreenPlan.Web/wwwroot` | стили с тёмной и светлой темой (по системе, переключатель в шапке), скрипты загрузки и статуса |
| `src/GreenPlan.Web/Services/EngineClient` | типизированный `HttpClient` к движку; ошибки сервиса → `EngineRequestException` |
| `src/GreenPlan.Web/Endpoints/ArtifactEndpoints` | прокси файлов результата `/jobs/{id}/artifacts/{name}` |
| `tests/GreenPlan.Web.Tests` | xUnit: клиент на подменном `HttpMessageHandler`, страницы через `WebApplicationFactory`, тест стиля |

## Запуск

Сначала движок (в отдельном окне):

```bash
greenplan serve --port 8000
```

Затем веб:

```bash
dotnet run --project web/src/GreenPlan.Web
```

Интерфейс — `http://localhost:5000`, Swagger движка — `http://localhost:8000/docs`.

## Настройки

`appsettings.json`, секция `Engine` (переопределяется переменными окружения):

| Ключ | Переменная | По умолчанию |
|---|---|---|
| `BaseUrl` | `Engine__BaseUrl` | `http://localhost:8000/` |
| `Timeout` | `Engine__Timeout` | `00:10:00` |
| `MaxUploadBytes` | `Engine__MaxUploadBytes` | 2 ГиБ |

В Docker Compose адрес движка — `http://engine:8000/`.

## Параметры расчёта

Панель «Параметры расчёта» отправляет движку только изменённые значения полем `settings`
(JSON с теми же разделами, что YAML-файл настроек). Движок накладывает их поверх загруженного
YAML и проверяет имена и значения: неверный параметр возвращается с понятной ошибкой до постановки
расчёта в очередь. Пример YAML со всеми разделами — `config/run-config.example.yaml`.

## Оформление

Тёмная и светлая темы на токенах цвета в `wwwroot/css/site.css`: по умолчанию тема берётся из
системы, кнопка в шапке переключает её и запоминает выбор в браузере. Шрифты системные — сервис
работает офлайн, внешние ресурсы не загружаются.
